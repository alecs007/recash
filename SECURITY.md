# Security Policy

## Reporting a vulnerability

Please **do not report security issues in public GitHub issues, pull requests or
discussions.**

Instead, report it privately in one of these ways:

- Open a [private security advisory](https://github.com/alecs007/recash/security/advisories/new)
  on this repository (preferred), or
- Email **contact@recash.ro**.

Please include:

- What the issue is and how it can be exploited
- Steps to reproduce, or a proof of concept
- The affected area — a URL, an API route, or a file and line
- Anything you know about impact (what data or accounts are reachable)

You'll get an acknowledgement, and we'll let you know once the issue is fixed or
if we decide not to act on it. Please give us a reasonable window to release a
fix before disclosing publicly.

## Scope

In scope: this repository — the Next.js app and its `/api/v1` REST routes, the
WebSocket server (`ws-server/`), the MCP server (`mcp-server/`), authentication
and session handling, rate limiting, and anything that exposes more listing or
user data than intended.

Of particular interest: **any way to obtain a listing's exact address or a user's
phone number without being the counterparty to that collection.** Coordinates are
deliberately approximated for anonymous visitors and for all AI-facing tools;
a bypass of that is a valid report.

Out of scope: vulnerabilities in third-party services (MongoDB Atlas, Redis
providers, Resend, OAuth providers, Gemini, Anthropic) — report those to the
vendor. Findings that require an already-compromised machine or account, and
reports generated by automated scanners with no demonstrated impact, are also out
of scope.

## Please don't

While testing, don't run denial-of-service or load tests against a deployed
instance, don't access, modify or delete data belonging to other people, and
don't social-engineer users or staff. Test against your own local instance where
you can — setup takes a few minutes, see the [README](README.md).

## Secrets

This repository ships no credentials. All configuration comes from environment
variables documented in [`.env.example`](.env.example); `.env` is gitignored and
must never be committed. If you believe a secret has been committed, report it
privately using the process above rather than opening an issue.
